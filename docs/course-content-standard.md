# freetorick 自由至富 課文重點標示規範

本規範適用於平台**每一門課、每一堂課**。新增課程或修改課文時，沿用同一套閱讀節奏；文字課、影片課及後續正式課都適用。

## 每堂課的閱讀結構

1. 課文開始前放「本課重點」，用一至兩句話說清楚學員這堂課最應學會的判斷或操作；不要只重複課名。
2. 課文依學習順序拆成 `01 / KEY IDEA`、`02 / KEY IDEA` 等段落，從第一段到結尾段都要有重點。示範案例、操作檢查與總結段也不能略過。
3. 每個 KEY IDEA 段落在標題下方放一則「本段重點」，並在**同一段原課文**標出對應的關鍵句。每段以一處教學重點底色為原則，避免整頁都上色。
4. `keyIdea` 必須是原課文中逐字存在的一句或完整短句，且足以說明該段的核心方法、規則或判斷；不要選「下面這張表」「小晴是……」之類只有鋪陳作用的句子。若原文只有表格，先補一段能解釋表格用法的課文，再選關鍵句。
5. 保留原課文脈絡和資料來源。只在閱讀層加入提示與標示；修改原文後，同步校對 `keyIdea`，不能留下不再出現的句子。

## 色彩與版面

- 宮位等需要辨認的專有名詞：Luxkey 藍綠淡底。紫微課使用；其他領域若有專有名詞，先確認是否真的需要同級標示。
- 教學關鍵句：Luxkey 朱紅淡底並加粗。課首及每段重點都指向這類句子。
- 只使用上述兩種標示色，不用第三種底色。手機版檢查換行、對比與表格橫向捲動，避免底色遮蔽文字。

## 編輯與上線檢查

- 新課每個 `Lesson.sections` 都必須有 `keyIdea`；資料型別已要求此欄位。現有短篇示範課以教學段落首句建立重點，正式製作時仍須逐段人工校讀。
- 紫微 20 堂課的 167 段對照保存在 `src/ziwei-key-ideas.json`，課首總重點在 `src/ziwei-highlights.ts`。原課文在 `src/ziwei-lessons.json`，標示資料不應替代原文。
- 修改紫微課時執行 `npm run check:highlights`：檢查 20 堂課、課首重點、每段標題及關鍵句是否仍與原文一一對應。正式建置會先自動執行此檢查。發布前再抽看第一、中間和最後一堂的桌機、手機閱讀畫面，確認底色確實出現在原文而非只出現在提示卡。
- 上述結構、原文對照與手機閱讀檢查是之後所有課程的發布條件；完整課程也要檢查講師影片、練習與評量是否呼應每堂課的重點。
- 從其他網站匯入課文時，逐堂檢查「首頁」「點這裡」「左右滑動」「開啟原課」「下載」「報告」等指示是否仍指向本站真實功能。刪掉失效操作提示，將舊站產品導購改為本站可完成的練習；保留有教學作用且實際可用的表格與工具說明。紫微課的 20 句舊命盤滑動提示已移除，本站表格在手機版的有效滑動提示由介面提供。
